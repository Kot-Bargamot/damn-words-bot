# engbot — тренажёр активного английского в Telegram

Персональный бот на Go: превращает присланные слова, фразы и тексты в разговорные учебные единицы, ведёт базу грамматики в GitHub по заметкам с `#grammar` и проводит короткие тренировки на воспроизведение с интервальными повторениями.

Языковая модель — [Groq](https://console.groq.com/docs/structured-outputs) (по умолчанию `openai/gpt-oss-120b` в строгом режиме JSON-схемы).

Прокси опционален и задаётся **для всего контейнера**: `PROXY_URL` раскладывается в стандартные `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`, через него идут все исходящие запросы — Telegram, Groq, GitHub, а при сборке образа — загрузка Go-модулей.

## Запуск

```bash
docker build -t engbot .
```

Без compose:

```bash
docker run -d \
  --name engbot \
  --env-file .env \
  --restart unless-stopped \
  -v engbot-data:/app/data \
  engbot

docker build --build-arg HTTPS_PROXY=$PROXY_URL --build-arg HTTP_PROXY=$PROXY_URL -t engbot .
docker run -d --name engbot --restart unless-stopped --env-file .env -v engbot-data:/app/data engbot
```

Без Docker (Go 1.23+) прокси задаётся обычным `HTTPS_PROXY`:

```bash
set -a; . ./.env; set +a
HTTPS_PROXY=$PROXY_URL go build -o engbot . && HTTPS_PROXY=$PROXY_URL ./engbot
```

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | токен от @BotFather |
| `GROQ_API_KEY` | да | ключ из console.groq.com |
| `PROXY_URL` | нет | прокси для всего контейнера (`http`, `https`, `socks5`, `socks5h`; логин/пароль в URL) |
| `ALLOWED_USER_ID` | да | единственный пользователь бота |
| `GITHUB_REPO` | да | публичный репозиторий `owner/name` |
| `GITHUB_TOKEN` | для записи | без него грамматика хранится только локально |
| `GITHUB_BRANCH` | нет | по умолчанию `main` |
| `GROQ_MODEL` | нет | по умолчанию `openai/gpt-oss-120b` |
| `GROQ_RESPONSE_FORMAT` | нет | `strict` (по умолчанию), `best_effort` или `json_object` — для моделей без поддержки строгой схемы |
| остальные | нет | см. `.env.example` |

Для `socks5h` DNS-имена разрешаются на стороне прокси — удобно, если локальный DNS блокирует адреса API. Если `HTTPS_PROXY`/`HTTP_PROXY` переданы в контейнер явно, они важнее `PROXY_URL`; `NO_PROXY` по умолчанию — `localhost,127.0.0.1,::1`.

Строгий режим JSON-схемы Groq поддерживает не все модели. Если сменили модель и получаете ошибки 400 — поставьте `GROQ_RESPONSE_FORMAT=json_object`: схема уйдёт в инструкцию, а ответ всё равно проверит валидатор бота.

## Как пользоваться

- Любое сообщение — лексика: бот выделит до 7 разговорных выражений (кнопки «Посмотреть», «Отменить добавление»).
- `#grammar …` — грамматическая заметка → `grammar/<тема>.md` в репозитории. Бот берёт правила только из заметки; при противоречии спрашивает: заменить, сохранить как уточнение или отменить.
- `/train` или «Тренироваться» — 5 заданий (каждое второе совмещено с изученной грамматикой) и мини-диалог. Во время тренировки обычный текст — это ответ; лексику добавлять через `/add …`.
- Кнопки: «Подсказка», «Показать ответ», «Пропустить», «Подробнее», «Не согласен» (оспоренная оценка не влияет на расписание), «Закончить».
- `/progress`, `/grammar`, `/stop`, `/help`.

## Приватность и источники

- Исходные сообщения **не сохраняются** ни в БД, ни в очередях, ни в логах. Хранятся только производные данные (выражения, значения, пункты правил, результаты проверок) и ссылка на сообщение: `chat_id`, `message_id`, URL.
- Тексты ответов на тренировке тоже не сохраняются; текст мини-диалога живёт только в памяти.
- В репозитории нет каталога `sources/`: в разделе «Источники» каждого документа — ссылки на сообщения Telegram.
- **Ограничение Telegram:** у сообщений личного чата с ботом нет открываемых ссылок. В этом случае бот сохраняет идентификаторы и пишет «прямая ссылка недоступна», фиктивных URL не создаёт. Если нужны рабочие ссылки — добавьте бота в свою приватную супергруппу (отключив privacy mode у @BotFather: `/setprivacy` → Disable) и пишите там: ссылки будут вида `https://t.me/c/<id>/<msg>`.
- Модель получает текст сообщения для обработки; условия хранения на стороне Groq определяются условиями Groq API, а не этим приложением.

## Надёжность

- Если Groq недоступен до извлечения — бот честно говорит, что материал не сохранён, и просит прислать его снова (текст не кладётся в очередь — так требует запрет на хранение оригиналов).
- Синхронизация с GitHub идёт из очереди с повторами; тренировки работают по локальной копии грамматики.
- Если файл в GitHub изменён вручную, бот не перезапишет его молча — предложит кнопку «Перезаписать версией бота».
- После перезапуска бот предлагает продолжить незавершённую тренировку новым заданием.
- Резервная копия — файл SQLite (`/app/data/engbot.db`, вместе с `-wal`), например: `sqlite3 engbot.db ".backup backup.db"`. Восстановление — положить файл обратно в том данных.

## Устройство

| Файл | Что внутри |
|---|---|
| `main.go`, `config.go` | запуск, переменные окружения |
| `docker-entrypoint.sh` | `PROXY_URL` → прокси для всего контейнера |
| `telegram.go` | Bot API, общий HTTP-клиент с прокси из окружения, ссылки на сообщения |
| `groq.go` | клиент Groq: structured outputs, повторы, 429/`retry-after`, исправление невалидного ответа |
| `llm.go` | промпты (версия `PromptVersion`), JSON-схемы и валидация операций |
| `store.go` | SQLite: схема и запросы |
| `srs.go` | лестница интервалов и классификация результата |
| `grammar.go`, `github.go` | слияние пунктов, Markdown, запись через GitHub Contents API |
| `bot.go`, `train.go`, `progress.go` | диалоговая логика |

Модель не получает токенов и доступа к SQL/GitHub: она возвращает JSON, а Go-код проверяет его и решает, что сохранить.

Тесты: `go test ./...` (интервалы, классификация, ссылки, грамматика, отсутствие исходного текста в БД, прокси из окружения для Telegram, Groq и GitHub, совместимость схем со строгим режимом Groq).
